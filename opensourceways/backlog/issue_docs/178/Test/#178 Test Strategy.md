### 3.1 功能测试专项

> 参考测试设计方向
> * API 语义验证：验证 HTTP 状态码（2xx, 4xx, 5xx）的使用是否符合 RESTful 规范。
> * 边界与非法输入：验证大数据量、空字段、特殊字符及非法 JSON 格式的拦截能力。
> * 业务状态机闭环：验证资源从"创建中"到"运行中"再到"已释放"的全生命周期逻辑。

**1. OTP 发送接口正常流程验证**：调用 `POST /api/v1/account/delete/send-otp`，选择邮箱渠道发送验证码。

* **对应 task 链接:** https://github.com/opensourceways/backlog/issues/178
* **预期结果**: 接口返回 200，用户邮箱收到 6 位数字验证码，Redis 中可查到对应 Key（TTL≤300s）。

**2. OTP 正确校验后账号删除成功**：使用有效 OTP 调用 `DELETE /api/v1/account`，完成账号删除。

* **对应 task 链接:** https://github.com/opensourceways/backlog/issues/178
* **预期结果**: 接口返回 200，账号从数据库中删除，Redis 中 OTP Key 同步销毁。

**3. OTP 过期后拒绝删除**：等待 5 分钟（TTL 过期）后使用原验证码调用删除接口。

* **对应 task 链接:** https://github.com/opensourceways/backlog/issues/178
* **预期结果**: 接口返回 400，错误码 `invalid_otp`，账号未被删除。

**4. 不携带 OTP 直接调用删除接口**：请求体中不包含 `otp` 字段。

* **对应 task 链接:** https://github.com/opensourceways/backlog/issues/178
* **预期结果**: 接口返回 400，拒绝执行删除，账号数据不变。

**5. 连续输入错误 OTP 超过 3 次后操作锁定**：连续提交错误验证码 3 次后再次尝试。

* **对应 task 链接:** https://github.com/opensourceways/backlog/issues/178
* **预期结果**: 第 4 次调用返回 423，Redis 中 OTP 记录被清除，用户需重新发起发送流程。

### 3.2 体验测试专项

> 参考测试设计方向
> * 无效引导：是否有空数据界面设计，引导用户去执行操作；是否滥用用户引导；是否有不可点击的效果。
> * 页面易用性：菜单层次是否太深；网站页面是否过长，内容过多，引起浏览者视觉疲劳；一次是否载入太多的数据；交互流程分支是否太多。
> * 设计易用性：标签页是否跟内容没有从属关系，当切换标签的时候，内容跟着切换；操作应该有主次从属关系；导航是否友好，不知如何返回上一页，不知当前页面在哪个栏目下；过于复杂的验证码，不清晰的验证码。
> * 页面性能：页面加载，下载时间是否过长，是否在合理的加载范围内；页面是否有过多新窗口，大量占用计算机资源。
> * 页面信息：是否有死链接或者链接错误；是否有页面安全信息；过于复杂的验证码，不清晰的验证码。

**1. 联系方式脱敏显示验证**：进入删除账号弹窗，检查已绑定邮箱和手机号的展示内容。

* **对应 task 链接:** https://github.com/opensourceways/backlog/issues/178
* **预期结果**: 邮箱显示为 `z***@example.com` 格式，手机号显示为 `138****8888` 格式，不暴露完整信息。

**2. 发送按钮冷却倒计时验证**：点击"发送验证码"后，检查按钮状态变化。

* **对应 task 链接:** https://github.com/opensourceways/backlog/issues/178
* **预期结果**: 按钮进入不可点击状态并显示 60 秒倒计时，倒计时结束后恢复可点击。

**3. 错误提示剩余次数展示**：输入错误验证码，检查页面提示信息。

* **对应 task 链接:** https://github.com/opensourceways/backlog/issues/178
* **预期结果**: 每次错误后提示"验证码错误，还剩 N 次机会"，第 3 次错误后提示"操作已锁定，请重新发起"。

### 3.3 集成测试专项

> 参考测试设计方向
> * 协议兼容性：验证不同版本的组件间（如旧版网关与新版后端）通过 gRPC/HTTP 通信的兼容性。
> * 分布式事务/最终一致性：验证跨数据库操作或跨服务调用时，在网络波动下的数据对齐情况。
> * 全链路追踪覆盖：确保 TraceID 在所有微服务节点间透传，无断链现象。

**1. 端到端删除全链路验证**：从前端发起删除操作，覆盖完整流程（发送OTP → 输入OTP → 确认删除 → 跳转完成页）。

* **对应 task 链接:** https://github.com/opensourceways/backlog/issues/178
* **预期结果**: 全链路无报错，账号数据从数据库删除，前端跳转至注销完成页，Redis OTP Key 已清除。

**2. 通知服务对接验证**：验证账号服务调用通知服务发送邮件/短信的链路正常。

* **对应 task 链接:** https://github.com/opensourceways/backlog/issues/178
* **预期结果**: 邮件和短信渠道均可正常收到 OTP，通知服务调用响应时间 ≤ 3s。

**3. Redis OTP 状态一致性验证**：在并发场景下（同一用户两个会话同时发起删除），验证 OTP 状态的一致性。

* **对应 task 链接:** https://github.com/opensourceways/backlog/issues/178
* **预期结果**: 后发起的 OTP 覆盖先发起的，同一时刻只有一个有效 OTP，不存在竞争条件导致的状态错误。

### 3.4 安全与隐私测试专项

> 参考测试设计方向
> * 最小特权原则 (PoLP)：验证服务账户（Service Account）是否无法越权操作未授权的资源。
> * 软件供应链审计：通过 SBOM 检查，验证容器镜像中是否存在已知的高危 CVE 漏洞。
> * 敏感信息外泄防护：检查日志、监控指标及 API 报错中是否夹带了明文密钥或隐私数据。

**1. OTP 日志脱敏验证（对应 SEC-T4）**：触发 OTP 发送和校验后，检查服务端日志内容。

* **对应 task 链接:** https://github.com/opensourceways/backlog/issues/178
* **预期结果**: 日志中不出现 OTP 明文，OTP 相关字段均显示为 `***` 或不记录。

**2. Redis OTP 存储安全验证（对应 SEC-T1）**：直接查看 Redis 中存储的 OTP Key 内容。

* **对应 task 链接:** https://github.com/opensourceways/backlog/issues/178
* **预期结果**: Redis 中存储的值为 HMAC-SHA256 哈希，不可通过 Redis 直接还原出明文 OTP。

**3. OTP 一次性使用验证（对应 SEC-T3）**：使用同一 OTP 连续调用两次删除接口（首次成功后再次调用）。

* **对应 task 链接:** https://github.com/opensourceways/backlog/issues/178
* **预期结果**: 第二次调用返回 400 `invalid_otp`，OTP 验证通过后 Redis Key 已被清除，无法重放。

**4. 鉴权绕过测试（对应 SEC-T2）**：无 Token 或 Token 过期时调用 OTP 发送和删除接口。

* **对应 task 链接:** https://github.com/opensourceways/backlog/issues/178
* **预期结果**: 接口统一返回 401 Unauthorized，不执行任何业务逻辑。

**5. 跨用户越权操作验证**：使用用户 A 的 Token 尝试触发用户 B 账号的删除流程。

* **对应 task 链接:** https://github.com/opensourceways/backlog/issues/178
* **预期结果**: 接口返回 403 Forbidden，用户 B 账号数据不受影响。

**6. API 响应隐私验证（对应 SEC-T5）**：检查 OTP 发送接口的响应体内容。

* **对应 task 链接:** https://github.com/opensourceways/backlog/issues/178
* **预期结果**: 响应体中不包含用户完整邮箱或手机号，仅返回发送成功状态和有效期。
