## 2. 需求场景说明

> 描述"在什么情况下，为了解决什么问题，用户需要做什么"。

**场景说明:**

随着欧拉、昇思开展开源实习，近期新增vllm-ascend参与开源实习，参与项目增多。社区管理员需要通过统一的数据管理看板：

1. **任务认领跟踪场景**：管理员需要查看任务认领情况，区分"认领申请人"（初次申请认领的学员）和"认领者"（经导师确认后实际开发的学员）
2. **导师提醒场景**：管理员需要及时通知导师确认学员的认领申请，避免任务分配延迟
3. **多项目管理场景**：管理员需要统一管理多个开源实习项目（欧拉、昇思、vllm-ascend）的任务状态

## 3 需求验收标准

> 明确需求完成的标志，必须是可量化、可测试的。

**验收标准:**

- [ ] 运营数据看板新增"认领申请人"字段，定义为任务初次被 `/intern-assign` 的用户
- [ ] 保留现有"认领者"字段（经导师确认后实际进行任务开发的用户）
- [ ] 看板支持多项目（欧拉、昇思、vllm-ascend）的统一展示
