### 3.1 功能测试专项

> 参考测试设计方向
> * API 语义验证：验证 HTTP 状态码（2xx, 4xx, 5xx）的使用是否符合 RESTful 规范。
> * 边界与非法输入：验证大数据量、空字段、特殊字符及非法 JSON 格式的拦截能力。
> * 业务状态机闭环：验证资源从"创建中"到"运行中"再到"已释放"的全生命周期逻辑。

**1. 数据预处理模块验证**

* **对应task**: TASK1 - 数据预处理模块开发
* **测试场景**:
  - 正常数据清洗和标准化
  - 缺失关键字段的数据标记
  - 特殊字符和格式异常处理
  - 大数据量处理性能
* **预期结果**:
  - 所有接入平台的数据均经过清洗和标准化
  - 缺失关键字段的数据被正确标记或过滤
  - 异常数据被正确处理，不影响整体流程
  - 处理性能满足需求（支持百万级用户数据）

**2. ID Mapping 算法验证**

* **对应task**: TASK2 - ID Mapping 算法实现
* **测试场景**:
  - 基于邮箱的匹配
  - 基于用户名的匹配
  - 多平台账号的OneID计算
  - 匹配策略和阈值配置
* **预期结果**:
  - 同一用户在不同平台的账号能正确映射到同一 OneID
  - ID Mapping 准确率 ≥ 95%
  - 每个OneID对应唯一的用户身份，无重复映射

**3. 映射结果存储与查询接口验证**

* **对应task**: TASK3 - 映射结果存储与查询接口
* **测试场景**:
  - 映射关系持久化存储
  - OneID 反查平台账号信息
  - 映射结果完整性验证存储
  - 查询接口性能测试
* **预期结果**:
  - 映射关系成功存储到数据库
  - 能通过 OneID 反查到原始平台账号信息
  - 映射结果可追溯性满足需求
  - 查询接口响应时间满足性能要求

### 3.2 体验测试专项

> 参考测试设计方向
> * 无效引导：是否有空数据界面设计，引导用户去执行操作；是否滥用用户引导；是否有不可点击的效果。
> * 页面易用性：菜单层次是否太深；网站页面是否过长，内容过多，引起浏览者视觉疲劳；一次是否载入太多的数据；交互流程分支是否太多。
> * 设计易用性：标签页是否跟内容没有从属关系，当切换标签的时候，内容跟着切换；操作应该有主次从属关系；导航是否友好，不知如何返回上一页，不知当前页面在哪个栏目下；过于复杂的验证码，不清晰的验证码。
> * 页面性能：页面加载，下载时间是否过长，是否在合理的加载范围内；页面是否有过多新窗口，大量占用计算机资源。
> * 页面信息：是否有死链接或者链接错误；是否有页面安全信息；过于复杂的验证码，不清晰的验证码。

不涉及，原因：本需求为批处理算法，不涉及用户界面交互。

### 3.4 安全与隐私测试专项

> 参考测试设计方向
> * 最小特权原则 (PoLP)：验证服务账户（Service Account）是否无法越权操作未授权的资源。
> * 软件供应链审计：通过 SBOM 检查，验证容器镜像中是否存在已知的高危 CVE 漏洞。
> * 敏感信息外泄防护：检查日志、监控指标及 API 报错中是否夹带了明文密钥或隐私数据。

**1. 日志脱敏验证**

* **对应task**: SEC-TASK1 - 实现日志脱敏过滤器，过滤敏感信息
* **测试场景**:
  - 日志中包含用户邮箱的脱敏
  - 日志中包含用户名的脱敏
  - 日志中包含其他敏感信息的脱敏
  - 异常日志的脱敏
* **预期结果**:
  - 日志中不包含明文用户邮箱
  - 日志中不包含明文用户名
  - 其他敏感信息被正确脱敏
  - 异常日志中的敏感信息也被脱敏

**2. 映射结果完整性校验验证**

* **对应task**: SEC-TASK2 - 实现映射结果完整性校验机制
* **测试场景**:
  - 正常映射结果的完整性校验
  - 篡改映射结果后的校验失败
  - 校验和算法的正确性
  - 完整性校验的性能影响
* **预期结果**:
  - 正常映射结果通过完整性校验
  - 篡改后的映射结果校验失败
  - 校验和算法准确可靠
  - 完整性校验不影响整体性能

**3. 数据库访问控制验证**

* **对应task**: 架构设计 - 数据安全
* **测试场景**:
  - 批处理任务账号的数据库访问权限
  - 未授权账号的访问拒绝
  - 最小权限原则验证
  - 数据库连接的安全性
* **预期结果**:
  - 批处理任务账号只能访问授权的表和字段
  - 未授权账号无法访问映射结果
  - 遵循最小权限原则
  - 数据库连接使用加密传输

### 3.5 可靠性与韧性专项

> 参考测试设计方向
> * 优雅降级与熔断：验证当外部依赖响应极慢时，系统是否能快速切换到"断路"状态以保护自身。
> * 自愈能力 (Chaos Engineering)：验证 Pod 被随机 Kill 或节点网络分区后，流量是否能自动漂移并恢复。
> * 幂等性验证：验证同一请求重试多次后，系统状态和数据是否保持唯一，无重复记录。

不涉及，原因：本需求为批处理任务，非长驻服务，不涉及可靠性与韧性设计。
