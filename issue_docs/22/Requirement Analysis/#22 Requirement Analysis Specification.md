## 2. 需求场景说明

> 描述"在什么情况下，为了解决什么问题，用户需要做什么"。

**场景说明:**

当前 GitHub / Gitcode 基础设施仓库中存在大量漏洞类 Issue 积压，其中部分漏洞已在保护分支上完成修复，但对应 Issue 仍处于 Open 状态，需要人工逐一核查并关闭，耗时耗力且容易遗漏。

为解决上述问题，需要一个定时任务，自动扫描各基础设施仓库保护分支的当前漏洞状态，将已修复（漏洞不再存在）的漏洞 Issue 自动关闭，从而消除积压、提升自动化效率。

---

## 3. 需求验收标准

> 明确需求完成的标志，必须是可量化、可测试的。

**验收标准:**

- 定时任务按配置周期（如每日一次）自动触发，无需人工干预。
- 对 GitHub 和 Gitcode 基础设施仓库的保护分支，能正确识别漏洞是否已修复。
- 已修复的漏洞 Issue 自动关闭，关闭时附带说明注释（如：漏洞已在保护分支修复，自动关闭）。
- 未修复的漏洞 Issue 保持 Open 状态，不误关。
- 经测试，积压漏洞 Issue 的人工关单工作量减少 ≥ 80%。
