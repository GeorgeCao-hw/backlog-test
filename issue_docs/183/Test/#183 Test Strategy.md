### 3.2 体验测试专项

> 参考测试设计方向
> * 无效引导：是否有空数据界面设计，引导用户去执行操作；是否滥用用户引导；是否有不可点击的效果。
> * 页面易用性：菜单层次是否太深；网站页面是否过长，内容过多，引起浏览者视觉疲劳；一次是否载入太多的数据；交互流程分支是否太多。
> * 设计易用性：标签页是否跟内容没有从属关系，当切换标签的时候，内容跟着切换；操作应该有主次从属关系；导航是否友好，不知如何返回上一页，不知当前页面在哪个栏目下；过于复杂的验证码，不清晰的验证码。
> * 页面性能：页面加载，下载时间是否过长，是否在合理的加载范围内；页面是否有过多新窗口，大量占用计算机资源。
> * 页面信息：是否有死链接或者链接错误；是否有页面安全信息；过于复杂的验证码，不清晰的验证码。

### 3.4 安全与隐私测试专项

> 参考测试设计方向
> * 最小特权原则 (PoLP)：验证服务账户（Service Account）是否无法越权操作未授权的资源。
> * 软件供应链审计：通过 SBOM 检查，验证容器镜像中是否存在已知的高危 CVE 漏洞。
> * 敏感信息外泄防护：检查日志、监控指标及 API 报错中是否夹带了明文密钥或隐私数据。

**1. CANN API Token凭证管理验证**

* **对应task**: SEC-TASK1 - 配置CANN API Token Secret
* **测试场景**:
  - 代码中无硬编码Token
  - 日志中无完整Token信息（仅显示"Token已使用"）
  - Token过期后服务正确报错，不泄露详细信息
* **预期结果**:
  - 代码扫描无硬编码凭证
  - 日志脱敏生效，无敏感信息泄露
  - 错误信息不含Token内容

**2. 日志脱敏验证**

* **对应task**: SEC-TASK2 - 实现日志脱敏
* **测试场景**:
  - 采集日志不记录完整API Token
  - 日志不记录敏感的executor_detail完整内容
  - 错误日志不含数据库连接字符串或密码
  - 日志仅记录操作类型、时间戳、状态统计
* **预期结果**:
  - Token在日志中显示为"***"或"已使用"
  - executor_detail仅显示必要字段（如用户名）
  - 数据库连接信息脱敏
  - 日志内容安全，可公开审计

**3. APIMagic API认证鉴权验证**

* **对应task**: SEC-TASK3 - APIMagic API添加认证鉴权中间件
* **测试场景**:
  - 无Token请求：返回401 Unauthorized
  - 过期Token请求：返回403 Forbidden
  - 有效Token请求：返回200和数据
  - 非授权用户Token：返回403 Forbidden（无访问权限）
* **预期结果**:
  - 无认证请求被拒绝，不返回数据
  - 过期或无效Token被拒绝
  - 有效Token正确授权
  - 权限控制生效，非授权用户无法访问

**4. SQL注入防护验证**

* **对应task**: SEC-TASK4 - SQL查询参数化
* **测试场景**:
  - 在查询参数中注入SQL语句（如：status='success; DROP TABLE ci_pipeline_runs')
  - 在时间参数中注入恶意SQL
  - 在分页参数中注入非数字字符
* **预期结果**:
  - 恶意参数被过滤或拒绝
  - SQL注入攻击不生效，数据库不受影响
  - 返回400 Bad Request或安全错误信息
