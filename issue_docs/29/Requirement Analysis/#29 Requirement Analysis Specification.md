## 2. 需求场景说明

> 描述"在什么情况下，为了解决什么问题，用户需要做什么"。

**场景说明:** 白帽安全测试发现中台暴露大量 Swagger API 文档接口，攻击者可借此获取完整 API 结构进而发现更多安全问题。需要开发自动化扫描工具，基于服务开放清单全量排查 Swagger 暴露情况，并建立定期扫描机制防止新增暴露。

## 3 需求验收标准

> 明确需求完成的标志，必须是可量化、可测试的。

**验收标准:**

- 扫描覆盖服务开放清单中的所有服务
- 能检测常见 Swagger 端点（`/swagger-ui.html`、`/v2/api-docs`、`/v3/api-docs` 等）
- 输出结构化扫描报告（服务名、地址、暴露端点、状态码）
- 支持定时触发，新增暴露时发送告警通知

---

## 4. 需求设计与分解

> 说明：基于初步方案，将需求拆解为可实施的原子 Task。后续的流程判定将严格依据这些 Task 的影响范围进行。

### 4.1 核心逻辑方案

> 简述实现逻辑（如：数据流向、模块改动、新增配置项等），作为任务拆解的理论依据。图片文字形式不限。

**逻辑方案:** 从服务开放清单获取目标地址列表，对每个地址探测常见 Swagger 路径，通过 HTTP 状态码 + 响应内容特征判定是否暴露，汇总生成报告。通过 cron 定时触发并对比增量告警。

### 4.2 任务清单

**任务清单:**

| 任务 ID | 任务描述 (Task Description) | 预期产出 (Deliverables) | 预期工作量（人天） |
|---------|----------------------------|------------------------|----------------|
| **TASK1** | 开发扫描核心模块（清单解析 + 端点探测 + 结果判定 + 报告生成） | 扫描工具代码、报告模板 | 3 |
| **TASK2** | 实现定时扫描与增量告警（cron 触发 + 差异对比 + 通知） | 定时任务配置、告警代码 | 1 |
| **TASK3** | 首次全量扫描执行与暴露清单输出 | 扫描报告、整改工单 | 1 |

**预计总工作量**: 5 人天
